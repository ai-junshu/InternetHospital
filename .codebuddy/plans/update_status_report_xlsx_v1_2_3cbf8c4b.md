## 技术栈

- 语言：Python 3（已装 openpyxl，环境 Node v24 / Python 可用）
- 库：openpyxl（精准读写 xlsx，保留样式与合并区域）
- 执行方式：编写一次性临时脚本 `_patch_xlsx.py`，用 openpyxl `load_workbook` 后按单元格坐标赋值，`save` 覆盖原文件，跑完即删脚本（遵循"临时文件验证后删除"约定）

## 实现方案

采用"只读探查 + 坐标定点改写"策略：已在准备阶段用 openpyxl 导出全部 6 个 sheet 的非空单元格与合并区域，确认了每个待改单元格的精确坐标（如 B3/B4/D4/F4、A13、A21、A29、D37、B32、下周计划 G 列、风险 F 列、技术架构 C7/C8 等），因此脚本只做 `ws.cell(r,c).value = new_str` 赋值，不触碰合并区域、不新增/删除行列、不重置样式，最大化降低回归风险。

### 关键技术决策

1. **保留 Workbook 对象整体 save**：openpyxl 加载后 `save` 会保留原 sheet 结构、合并单元格、字体/填充等样式（仅修改目标单元格的 value），满足"不破坏格式"要求。
2. **文本追加而非覆盖**：A13 总体结论采用"原文本 + 换行 + 08-02 段"方式，避免丢失历史叙述。
3. **数值与状态分列处理**：完成度（A21/A29 百分比）、状态（下周计划 G 列、风险 F 列）各自独立赋值，不互相影响。
4. **新增行追加**：本周完成事项在 A31 之后追加 #26-#34（保持原表头 A5/F5 列语义：#/模块/阶段/完成事项/验证结果/负责人），不插入中间行以免破坏合计行定位（合计在 A32，追加行插在 A31 与 A32 之间需先下移；更稳妥做法：将 #26-#34 直接写到 A31 起始并整体下移合计行——脚本用 `ws.insert_rows(31, 9)` 后在 31-39 写数据，原 32 合计行自动下移到 41）。

### 性能与可靠性

- 单次脚本执行，IO 仅一次 load + 一次 save，无循环遍历全表重写，开销可忽略。
- 所有新文本为硬编码常量，无外部依赖、无网络，幂等可重跑（重跑前 git 无变更则安全；脚本跑完即删，不残留）。
- 完成后用 openpyxl 重新 load 校验关键单元格值，并打印校验结果确认。

## 实现注意事项

- 不修改 docx/md 等其他文件（用户仅要求改 xlsx）。
- 不改动 P0 资质等"未启动"风险项的"状态"列原始语义，仅在已落地项上校正。
- 脚本写完后立即删除临时文件（用户已授权"验证后不需要的临时文件直接删"）。
- save 后建议用 `git diff --stat` 确认仅 xlsx 变更、且文件可正常打开。
