# 深化三任务实施计划（2026-08-01）

## 背景
P1/P2/P3 主框架已落地（提交 b1b9648），但三处仍是占位/硬编码，需深化为可运营能力：

1. **采集器配置化**：`data_asset_collector.py` 用硬编码 `_COLLECTORS` 字典 + 字符串包含匹配，新增资产须改代码。改为「声明式配置 + 类型化调度」。
2. **P3 真实建表/建集合**：`iceberg_client.py`/`milvus_client.py` 为占位骨架（pyiceberg/pymilvus 缺失时返回 None，且 `ensure_*` 未真正建表/建集合）。补全真实 DDL/DDL-less 建表逻辑 + 管理端点。
3. **模型接入 MLflow registry**：`model_loader.py` 已支持 registry 加载，但 (a) 训练脚本 `train_sample.py` 特征列与推理 API 的 DataFrame 列不一致，加载会因为列错位失败；(b) 缺 registry 版本/健康查询端点。补齐特征契约对齐 + registry 端点。

## 实施步骤

### A. 采集器配置化
- 新增 `backend/app/services/collector_config.py`：声明式采集器配置（采集类型→聚合口径映射），支持 per-asset 覆盖。
- 改造 `data_asset_collector.py`：`collect_asset_metrics(db, asset)` 接收资产对象（或 name），按 `collector_type` 字段路由到通用聚合器（count/quality/agg），不再依赖硬编码字符串匹配。
- `data_assets.py` 的 `collect` 端点：传入资产对象；返回使用的采集器类型。
- 新增 `GET /collectors` 端点：列出已注册采集器（类型、匹配资产、聚合口径），便于运营透明。
- 测试：更新 `test_data_asset.py` 采集用例，验证配置化路由 + 新端点。

### B. P3 真实建表/建集合
- `iceberg_client.py`：`ensure_asset_table` 用 pyiceberg 真实建 `plat_data_asset` 表（namespace=ihm，列含 id/name/owner/sensitivity/quality/data_volume/valuation 等），幂等（exists 跳过）。
- `milvus_client.py`：`ensure_health_vector_collection` 真实建 768 维（健康画像 embedding）集合，带 IVF_FLAT 索引，幂等。
- 新增 `backend/app/api/v1/plat/lake_init.py`：仅 platform/xingyao 可调的初始化端点 `POST /data-lake/init`（建 Iceberg 表 + Milvus 集合），并 `GET /data-lake/status` 探测依赖可达性。config 增加 `milvus_dimension` 配置项。
- 测试：无依赖用例验证路由注册 + 依赖缺失时优雅降级（返回 available=False 不抛错）。

### C. 模型接入 MLflow registry
- 统一特征契约：新增 `ai-service/app/ml/feature_contract.py` 定义各模型输入列顺序。
- 改造 `train_sample.py`：用与推理一致的真实特征列训练（plan_recommend/repurchase/risk 各自的 DataFrame 列对齐推理 API）。
- 新增 `ai-service/app/api/model_registry.py`：`GET /models/registry` 返回各模型 registry 版本/stage/可达性，`GET /models/health` 探活。
- `model_loader.py`：增加 `list_registry()` 辅助 + 缓存失效防护。
- 测试：新增 `test_registry.py` 验证特征契约列对齐 + 端点路由注册（不依赖真实 MLflow server）。

## 验证
