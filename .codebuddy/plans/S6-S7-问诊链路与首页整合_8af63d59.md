## 用户需求

在迭代 A（S1-S5）已打通"患者复诊→医生开方→药师审核→凭方购药"的基础上，启动迭代 C 的 S6 与 S7：补齐患者侧问诊链路闭环，并将小程序首页/个人中心接入真实数据并补齐工程化骨架。

## 产品概述

- S6：让患者在小程序内自主发起在线复诊、查看会话、与医师图文沟通，并实现消息实时刷新（轮询），形成完整的"患者发起→医师接诊→双向沟通→结束"问诊链路。
- S7：将静态首页改造为真实数据驱动的门户（推荐医生、我的问诊入口、公告 banner 占位），个人中心接入真实身份，并引入 tabBar 统一导航与全局登录守卫，使小程序具备可演示的工程化形态。

## 核心功能

- 患者端"我的问诊"列表页：按当前患者过滤，支持选医生发起复诊（创建 open 态会话）。
- 患者端问诊会话页：气泡式图文消息、发送（sender_role=patient）、定时轮询医师回复、会话结束态提示。
- 医师端会话页实时化：定时轮询拉取消息，无需手动刷新即可看到患者新消息。
- 首页真实化：接入医生列表渲染推荐医生、增加"我的问诊"入口、本地公告/banner 占位（预留接口）、加载骨架态。
- 个人中心真实化：调用 /ih/users/me 获取真实角色并展示身份标识。
- 工程化：tabBar 统一导航（首页/复诊开药/我的）+ 全局登录守卫（无 token 自动跳转登录）。

## 技术栈选择

- 前端：Taro (React) 小程序、TypeScript、内联样式（与现有 13 页一致），沿用 `@/services/ih` 封装层。
- 后端：复用现有 FastAPI `ih` 路由（consultations / users / doctors），**不新增后端接口**。
- 联调：Python urllib（既有技术债：errors.py 对 curl 触发假 5000，统一用 urllib 验证）。

## 实现方案

### 总体策略

前端补齐患者侧问诊闭环 + 首页/个人中心真实化 + 工程化骨架，全部基于已验证的后端接口。核心决策：

1. **不改动后端**：`list_consultations` 已支持 `patient_id` 过滤与 role 权限隔离；`get_me` 已返回 `{user_id, role}`；`list_doctors` 已可用。新增两个前端封装函数即可。
2. **轮询而非 WebSocket**：现有后端无 WS 通道，采用 `setInterval`（3-5s）拉取 `listMessages`，`onUnmount/onUnload` 清除定时器，避免引入新依赖；延迟与开销可控（单会话分页 ≤200 条）。
3. **tabBar + 全局守卫**：在 `app.config.ts` 配 `tabBar`，在 `app.tsx` 的 `useLaunch`/`useDidShow` 中校验 token，缺失则 `reLaunch` 登录页，保持最小侵入。
4. **公告/banner 本地静态占位**：后端无公告数据域，使用本地常量并预留接口函数位（如 `getAnnouncements`），便于后续后端补齐后零改动接入。

### 性能与可靠性

- 轮询频率 4s，会话页卸载即清定时器，防止内存泄漏与重复请求。
- `listPatientConsultations` / `getDoctors` 使用分页（page_size 默认 20），避免全量拉取。
- `getMe` 在 `profile` 的 `onShow` 调用并兜底本地 Storage，网络异常不影响展示。

## 实现注意事项

- 沿用现有 `services/ih.ts` 的 `request` 封装（已注入 JWT、401 清理、统一 toast）。
- 患者发送消息使用 `sender_role: 'patient'`、`sender_id: 当前 patient_id`（取自 Storage）。
- `doctor-chat` 仅新增轮询逻辑，不改动已稳定的开方/结束状态机。
- 新增页面需在 `app.config.ts` 注册，否则 `navigateTo` 失败。
- tabBar 图标使用本地图片资源（或纯文字 tab），避免引入外部图片依赖。

## 架构设计

### 数据流（患者侧问诊）

```
患者首页/我的问诊 → patient-consult-list（listPatientConsultations）
  → 选医生 createConsultation(patient_id, doctor_id, chief_complaint)
  → patient-chat（listMessages 轮询 + sendMessage）
  ← 医师端 doctor-chat（startConsultation → 双向 sendMessage → endConsultation）
```

### 工程化结构

```
app.config.ts: pages[] + tabBar[]（首页/复诊开药/我的）
app.tsx: useLaunch 校验 token → 无则 reLaunch 登录页
```

```ts
// services/ih.ts 新增
export async function listPatientConsultations(params: {
  patient_id: number; page?: number; page_size?: number
}) {
  return request<Page<Consultation>>('GET', '/ih/consultations', { params })
}
export async function getMe() {
  return request<{ user_id: number; role: string }>('GET', '/ih/users/me')
}
```

## 设计风格

延续现有小程序简洁医疗风格（蓝白主色 #1677FF / #F5F7FA），无第三方组件库，使用内联样式保持与已有 13 页一致。新增患者会话页复用医师端气泡卡片样式（医师右/患者左），保证双端视觉统一。

## 页面规划（2 个新页 + 4 个改造页）

### 1. patient-consult-list（我的问诊）

- 顶部：标题"我的问诊" + "发起复诊"按钮
- 区块A：进行中会话（open/ongoing）高亮卡片，显示医师、主诉、状态
- 区块B：历史会话（ended）列表
- 区块C：发起复诊弹层 — 医生列表（接 getDoctors）单选 + 主诉输入

### 2. patient-chat（患者会话）

- 顶部：会话号 + 状态 + 医师信息
- 区块A：消息气泡区（ScrollView，患者左蓝/医师右白，复用 doctor-chat 样式）
- 区块B：底部固定输入栏（输入框 + 发送），会话 ended 时禁用并提示"问诊已结束"
- 区块C：轮询指示（轻量 loading），无感刷新

### 3. index（首页改造）

- 区块A：品牌区 + 服务须知弹窗（保留）
- 区块B：公告/banner 横条（本地静态，预留接口）
- 区块C：推荐医生横向卡片（接 getDoctors，头像/科室/职称）
- 区块D：服务入口（在线复诊/我的处方/去开药/健康档案/我的问诊）
- 区块E：加载骨架态

### 4. profile（个人中心改造）

- 用户卡片：真实 role 标识（患者/医师/药师）+ 脱敏手机号兜底
- 入口：我的订单/我的处方/健康档案
- 退出登录

### 5. tabBar（工程化）

- 首页 / 复诊开药 / 我的 三个 tab，纯文字或本地图标

### 6. 全局登录守卫

- app.tsx 启动校验 token，缺失自动跳转登录页
