## 产品概述

将现有 PRD V1.0（单一 2C 在线复诊定位）整体重构为 V2.0，确立**双主线并列**架构：主线一为互联网医院（2C 在线复诊+电子处方+药品销售，保留并优化现有功能）；主线二为健康数据中台（B2B2C 连锁门店赋能+数据资产化，全新构建）。依托星耀产业资本健康产业赋能服务投资平台的"合规大脑+医疗AI数据中台"能力，为连锁门店提供数字化基础设施，并将连续、结构化的治疗效果数据作为核心数据资产壁垒。

## 核心功能

### 互联网医院主线（保留优化）

- 用户端小程序：首页、找医生、找产品、复诊开药、个人中心/代理中心
- 医生端小程序：工作台、问诊聊天室、排班管理
- 互联网医院管理后台：合规监管看板、异常预警

### 健康数据中台主线（全新构建，完整功能级）

- **连锁门店管理后台 (2B)**：客户健康档案管理（疼痛评估量表、治疗记录、效果追踪、复购预测模型）、门店经营数据看板（到店率/转化率/客单价/复购率/NPS 实时监控）
- **调理师/健康顾问工作台 (2B)**：客户管理、调理方案制定与执行、治疗记录、依从性管理
- **健康数据中台管理后台 (2G)**：治疗数据沉淀（数据采集标准化、按疼痛类型/调理方案/产品组合结构化存储、数据资产管理、数据输出支撑产品迭代与融资估值）、AI辅助决策（风险画像、方案推荐、依从性管理、模型管理）

### 目标用户扩展（4类→7类）

保留原有 4 类用户，新增：连锁门店管理员 (2B)、调理师/健康顾问 (2B)、星耀产业资本/数据中台运营 (2G)

### 输出物

- V2.0 PRD Markdown 文件（新建，保留 V1.0 原文件）
- V2.0 PRD Word 文档（通过 docx skill 生成，含目录/页码/表格等专业排版）

## 技术方案

### 文档技术栈

- **主文件格式**：Markdown（.md），直接编写，保持与 V1.0 一致的 Markdown 语法风格（标题层级 `##`/`###`/`####`、表格、加粗、代码块）
- **Word 文档生成**：使用 docx skill（Python python-docx 库）从 Markdown 内容生成专业 .docx 文件，包含自动目录、页码、页眉页脚、表格样式
- **文件命名**：新建 `互联网医疗中心平台产品需求文档（PRD V2.0）.md` 和 `.docx`，V1.0 文件保留不动作为历史版本

### 实现要点

1. **内容连续性**：Part A 保留 V1.0 的 3.1-3.3 全部内容，仅调整章节编号和少量措辞以适配双主线语境，不破坏原有功能描述完整性
2. **新模块深度对齐**：Part B 的 3.4-3.6 每个子功能必须包含「功能描述」「子功能点」「数据需求」三段式结构，与 3.1-3.3 完全对齐
3. **数据资产主线贯穿**：从 1.1 产品概述到 5.2 数据资产生命周期，"数据资产"概念需在文档中形成闭环引用
4. **docx 生成质量**：使用 docx skill 生成时，需确保表格边框、标题样式（Heading 1-4）、代码块字体、产品结构图等特殊格式正确渲染

### 注意事项

- V1.0 原文件（.md 和 .docx）保持不动，V2.0 为新文件
- 产品结构图在 .md 中使用 ASCII 树形图（与 V1.0 风格一致），在 .docx 中可转换为 SmartArt 或保持文本缩进格式
- 数据字典表格需大幅扩展，覆盖门店管理、客户健康档案、治疗数据、AI模型管理等新增实体
