补齐三块前端（仅前端，复用既有后端端点，缺失端点以前端本地态实现并标注 gap），深度与已建 3.1/3.3 同级：可交互、对齐后端接口、能跑通主流程。

- **3.2 医生端小程序** → 放进 `code/mp-taro`（小程序工程）
- **3.4 连锁门店管理后台** → 放进 `code/admin-web`（web 工程）

## 产品概述

按 PRD V2.0 三大前台章节补齐空壳页：医生在手机端处理复诊问诊与开方；门店管理员在 web 后台做客户健康档案钻取与调理师调配；数据中台运营在 web 后台做合规大脑与治疗数据沉淀总览。

## 核心功能

### 3.2 医生端小程序（mp-taro）

- 登录页增加「医生入口」角色切换，选 doctor_id 存入 storage 进入工作台
- 医生工作台：今日数据卡片（待处理/接诊量/收入）、本人问诊会话列表
- 问诊聊天室：图文沟通（sender_role=doctor）、病历模板、开方 ModalForm（选药品+电子签名提交）、结束问诊
- 我的排班：设置可问诊时间段（本地态，标注后端 gap）

### 3.4 连锁门店管理后台（admin-web）

- 3.4.1 客户健康档案管理：客户列表增加「详情」抽屉，钻取疼痛评估/治疗记录/复购预测/风险画像
- 3.4.3 调理师调配：重建 `store/index` 占位页，做调理师列表（/mt/stores/{id}/therapists）+ 排班/客户分配/能力标签（本地态）

### 3.6 健康数据中台管理后台（admin-web）

- 3.6.1 合规大脑：新建页，复用 /plat/audit-logs 做数据使用监控与风险事件，采集字段合规清单配置化，对外输出审核关联 data-assets.usage_scope
- 3.6.2 治疗数据沉淀：新建页，汇总数据采集标准化说明、结构化存储三维（疼痛类型/方案/产品组合）、数据质量（quality_score）、资产目录链接

## 技术栈

- 小程序：`code/mp-taro`（Taro 3.6.23 + React + TypeScript，原生 `@tarojs/components` + 内联样式，医疗蓝 #1677FF，不引 UI 库）
- 后台：`code/admin-web`（React + Ant Design Pro / `@ant-design/pro-components` + antd，医疗蓝主题）
- 后端：复用既有 FastAPI 端点（`/ih/*`、`/mt/*`、`/plat/*`），本次不新增后端

## 实现方式

- 纯前端补齐，严格复用现有 services（`mp-taro/src/services/ih.ts`、`admin-web/src/services/{mt,plat}.ts`）与 API 常量（`src/constants/api.ts`）。
- 缺失端点（医生排班、调理师排班/分配/标签、合规大脑采集审核、药品目录）以组件本地 state + 注释标注 gap，保持与既有「机制级验证」一致；药品目录用本地常量列表占位。
- mp-taro 新页面在 `app.config.ts` 注册；admin-web 新页面在 `src/layouts/BasicLayout.tsx` 菜单追加，并遵循现有 ProTable/PageContainer/ModalForm 写法。

## 实现要点

- 性能：admin-web 列表沿用 `request` 分页（page/page_size），不一次性拉全量；mp-taro 列表分页拉取，避免大列表重渲染。
- 一致性：mp-taro 沿用 `request.ts` 拦截器与 `@/services/ih` 约定；admin-web 沿用 `services/mt.ts` 的 `PageResult<T>` 与 `http` 封装。
- 爆炸半径控制：仅改/增上述文件，不重构无关页面（repurchase/risk/ai-models/data-assets 已建好，不动）；不改动后端。
- 验证：mp-taro `npx tsc --noEmit` 0 错误；admin-web `npx tsc --noEmit` 或 `npm run build` 通过。

```ts
// mp-taro/src/services/ih.ts
export async function createPrescription(body: {
  patient_id: number; doctor_id: number; diagnose?: string;
  items_json: unknown; signature_url?: string;
}) // POST API.prescriptions
export async function listDoctorConsultations(params: { doctor_id: number; page?: number; page_size?: number; status?: string })
// admin-web/src/services/mt.ts
export async function listStoreTherapists(storeId: number, params?: { page?: number; page_size?: number })
```

两套前端均沿用既有视觉语言，不引入新设计体系。

**mp-taro（医生端小程序）**：Taro 原生组件 + 内联样式，医疗蓝主色 #1677FF，洁净白卡片 + 浅灰底；顶部导航标题 + 底部 Tab 切换（患者/医生角色），聊天室用左右气泡区分医患，开方用底部弹起 ModalForm。整体保持轻量、移动端友好的卡片式布局。

**admin-web（门店/数据中台后台）**：复用 Ant Design Pro 既有主题（medical blue + PageContainer/ProTable/ProForm/ModalForm/Card/Statistic/Tag/Descriptions），左侧菜单分组（3.4 门店管理、3.6 数据中台），列表用 ProTable 分页，详情用 Drawer/ModalForm，概览用 Statistic 卡片。新页与已建 customer/data/ai-models/data-assets 视觉一致。
