## 用户需求

按建议顺序推进四项剩余代码缺口：S8 小程序中台域接入、医院管理后台核查补全、微信支付真链路、合理用药真引擎。

## 产品概述

本次为互联网医疗中心平台补齐四项关键能力缺口，覆盖健康数据中台前端、医院管理后台、交易支付链路与处方安全合规。后端主干接口已较完整，本次重点在"真实可用化"与"前端补全"。

## 核心功能

- S8 小程序中台域：新建 mp-taro 的 mt 域页面组（客户/疼痛评估/照护计划/治疗记录/复购/风险），接入服务层，打通健康数据中台主线前端闭环。
- 医院管理后台核查与补全：逐项核查 admin-web 的 ih/* 页面与后端 ih 7 模块对接情况，补全空缺子页面与字段（科室结构、药房管理、药师排班审核配置等）。
- 微信支付真链路（生产骨架）：补全 wxpay.py 真实 RSA 签名与 APIv3 下单调用、wxpay_verify.py 平台证书验签与 AES-GCM 回调解密、平台证书自动下载；保留 dev_sandbox 开关，交付真实实现与配置示例，不端到端验证。
- 合理用药真引擎：补全 HttpRxEngine 真实 httpx 调用并映射 RxResult；附本地 Mock 供应商服务（/v1/rx-check）使处方创建可端到端联调真引擎通路，生产仅需切换 RX_ENGINE_BASE_URL。

## 技术栈选择

- 后端：Python 3.11 + FastAPI + SQLAlchemy 2.0（Async）+ httpx + cryptography（微信 RSA/AES-GCM 必需）。
- 小程序：Taro（React）+ TypeScript，复用 `mp-taro/src/services/ih.ts` 与既有 pages 结构。
- 后台：React + Ant Design Pro，复用 `admin-web/src/routes/ih/*` 与 `services/` 封装。
- 配置：复用既有 `core/config.py` 的 wxpay_ *与 rx_engine_* 字段，dev 态默认走沙箱/Mock。

## 实现方式

### 总体策略

分四个独立 Phase 推进，复用现有模块与模式，不引入新业务概念；一次性验证脚本执行后删除，不进 git。

### Phase 1 合理用药真引擎（内部可验证，优先级最高）

- 改造 `app/services/rx_engine/http.py`：实现 `check()` 真实 httpx POST `{base_url}/v1/rx-check`，请求体遵循 `base.py` 的 RxResult 输入契约（patient.pregnancy/allergy + items[drug_name/dose/freq/daily_dose/max_daily_dose]），将响应映射为 `RxResult`（conflicts/contraindications/dosage_warnings/checked_at），异常向上抛出由 `prescriptions.create` 既有降级逻辑兜底。
- 新增 `scripts/mock_rx_provider.py`：轻量 FastAPI 服务暴露 `POST /v1/rx-check`，内置若干相互作用/禁忌/剂量规则模拟真实供应商；用 `uvicorn` 本地启动供联调。
- 配置：`.env` 设 `RX_ENGINE_PROVIDER=http`、`RX_ENGINE_BASE_URL=http://127.0.0.1:9099`；`prescriptions.create` 路径不变。
- 验证：起 Mock 供应商 + 起 backend + 开方（带孕期/过敏/日剂量）→ 断言 `rx_check_json.provider=="http"` 且告警按规则触发；联调通过后停服务、删脚本。

### Phase 2 微信支付生产骨架（不验证）

- `app/core/wxpay.py`：`_production_prepay` 实现 —— 用商户 API 私钥(pem)对 `POST\n{url}\n{timestamp}\n{nonce}\n{body}\n` 做 RSA-SHA256 签名，Authorization 头 `WECHATPAY2-SHA256-RSA2048`，POST `https://api.mch.weixin.qq.com/v3/pay/transactions/jsapi`，解析 prepay_id 并按 JSAPI 规则用私钥对 `appId/timeStamp/nonceStr/package` 做 paySign（RSA）。
- `app/core/wxpay_verify.py`：实现 `verify_notify`（按 `Wechatpay-Serial` 取平台证书公钥 RSA 验签）、`decrypt_resource`（cryptography AES-256-GCM 解密 resource.ciphertext）；新增平台证书自动下载（GET `/v3/certificates`，用 APIv3 key 解密后按 serial 缓存到内存/文件）。
- config：新增 `wxpay_private_key_path`（pem 路径）、`wxpay_cert_cache_dir`；`wxpay_dev_sandbox` 默认 True 不变，生产置 False。
- 交付 `.env.example` 注释示例与实现代码，不端到端验证（无凭证）。

### Phase 3 S8 小程序中台域前端

- 新建 `mp-taro/src/services/mt.ts`：封装 mt 域接口（customers/pain_assessment/care_plans/treatment_records/repurchase/risk 的列表/详情/创建），风格对齐 `services/ih.ts`。
- 新建 `mp-taro/src/pages/mt/*` 页面组：客户列表+授权、疼痛评估录入、照护计划查看、治疗记录录入、复购预测、风险画像；复用既有列表卡片与 Loading 模式，接入 tabBar/全局守卫（参照 S7 既有结构）。
- `app.config.ts` 注册新页面路由；确保与小程序的JWT角色体系（patient/store/therapist）一致。

### Phase 4 医院管理后台核查与补全

- 用 code-explorer 核查 `admin-web/src/routes/ih/*` 每个页面是否真实调用 `/api/v1/ih/*`、字段完整性、是否缺 PRD 3.3 要求的子页面。
- 依核查结果补全：可能缺口含科室结构管理、药房库存/药品目录管理、药师排班审核配置 UI、监管看板对接；缺页则按 Ant Design Pro 既有列表/表单页模式新建，复用 `services/` 中已有 ih 封装。

## 实现要点

- 性能：RxEngine/微信调用均带 timeout 与降级，不阻塞主链路；平台证书内存缓存避免重复下载。
- 安全：商户私钥/APIv3 key/证书仅从环境变量注入，不打印日志（等保三级）。
- 爆炸半径：仅改既有服务与新增页面，audit/权限/RLS 逻辑不变；一次性脚本不进 git。
- 复用：微信签名复用 cryptography；Mock 供应商复用 FastAPI；前端复用既有 services 与页面模式。
