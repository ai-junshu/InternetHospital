## 用户需求

用户已确认两条主线工作的下一步范围：

1. 迭代C联调收尾（工程）：采用 P0 必做档。
2. 健康数据中台主线：采用存量盘点 + 缺口清单档，不立即编写大量新业务代码。

## 产品概述

在已推送（1d47255 迭代A、ecd49fb 迭代C、c398ebc 报告V1.1）的基础上，闭环迭代C的安全与联调风险，并对健康数据中台主线已落地的代码资产做系统性盘点，输出可执行的缺口清单。

## 核心功能

- 修复 `end_consultation` 越权绕过：归属判定从查询参数改为 JWT 主体（`actor_of(_auth)` + 角色判定），对齐 `get_consultation` 的越权校验写法。
- 修复前端传参错位：`ih.ts` 的 `endConsultation` 移除对前端传入 id 的信任，`patient-chat` 调用同步修正，使患者端"结束会话"可用。
- 补充 consultation 后端测试：覆盖双端结束、2003 越权、归属过滤三个加固点，复用 `test_p6_endpoints.py` 的 ASGI + 令牌 + DB 不可达自动 skip 模式。
- 数据中台存量盘点：逐模块核实 10 个 mt 路由 + 12 张表 + RLS + admin-web 页面是否满足 PRD V2.0 强规则（方案关联医师ID、治疗记录留痕不可删、效果四档自动判定），并核实 AI 特征工程与数据资产血缘缺口，输出优先级缺口清单（Markdown 文档）。

## 技术栈

- 后端：Python + FastAPI（现有栈），pytest（已有 `testpaths=["tests"]`）
- 前端：Taro(React) 小程序（现有栈），TypeScript
- 文档：Markdown（用户偏好默认只输出 .md）

## 实现方案

### 迭代C P0 修复

- **end_consultation 加固**：移除 `doctor_id`/`patient_id` 查询参数信任，改为从 `_auth` 取 `actor_of(_auth)` 并按 `role`（patient/doctor）分别约束 `patient_id`/`doctor_id`，与 L131-136 的 `get_consultation` 越权逻辑保持一致，杜绝不传参绕过。
- **前端同步**：`ih.ts` 的 `endConsultation(consultationId)` 改为不再接收并拼接外部 id；`patient-chat/index.tsx` 调用改为 `endConsultation(id)`，消除患者传 patientId 当 doctor_id 的恒错 2003。
- **测试补齐**：新建 `tests/test_consultations.py`，复用 `test_p6_endpoints.py` 的 `httpx.ASGITransport` + `create_access_token(sub, role)` + DB 不可达 skip 骨架，覆盖三种角色（patient/doctor/platform）下的 list/get/end 行为。

### 数据中台盘点

- 以 PRD V2.0 四大模块为纲，对照 `code/backend/app/api/v1/mt/`、`app/models/mt_models.py`、`app/core/deps.py`、`admin-web/routes/**` 与 `ai-service/app/ml/feature_store.py`，逐项核实强规则落库情况与缺口，汇总为 Markdown 清单。不新增业务代码，仅产出文档与建议。

## 实现注意

- 修复 `end_consultation` 后须确认 `doctor-chat` 现有传 `doctorId` 的调用路径不回归（后端改为按 JWT 角色取主体后，前端 doctorId 参数可废弃）。
- 测试文件须保持与现有 pytest 配置兼容，避免引入新的 dev 依赖；DB 不可达时自动 skip，不阻塞 CI。
- 盘点文档只陈述事实与缺口，不做代码改动；临时文件按用户既往偏好保留、不主动删除，仅在清单中建议补充 .gitignore（根目录 mlruns/、verify*.txt、*_dump.txt）。
