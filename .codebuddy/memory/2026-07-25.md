## 验证中暴露的 2 个工程 bug（已修）
- **Bug3 · torch 传递依赖导致 MLflow sklearn loader DLL 初始化失败**：本机曾装过 `torch 2.10.0`（mlflow/sklearn 拉的传递依赖），但 torch 的 `c10.dll` 在 Python 3.14 下报 `WinError 1114 DLL初始化失败`（torch 尚未完全适配 3.14 / VC++ 运行时不匹配）。MLflow sklearn loader 遍历 `sklearn.externals.array_api_compat.torch` 触发 `import torch` → 整个模型加载链路 500。**我们的模型是纯 sklearn RandomForest，根本不需要 torch**。修复：`pip uninstall -y torch`，加载/推理均恢复正常。教训：CI/生产环境若无需 DL 框架，建议在 `ai-service/pyproject.toml` 排除 torch（`pip install -e . --no-deps` 或显式 `extras_require`）。
- **Bug4 · `model_loader.load_model` 返回的 `version` 是 int，schema 期望 str**：`MlflowClient.get_latest_versions(...).version` 返回 int，而 `PredictResponse.model_version: str` → pydantic ValidationError。修复：在 `app/ml/model_loader.py` 把 `version = str(...)` 强制转字符串。三接口 ValidationError 消失。
